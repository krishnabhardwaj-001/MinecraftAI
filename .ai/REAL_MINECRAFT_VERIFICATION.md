# Real-Minecraft 1.21.11 Verification Checklist & Protocol

## Overview
This document defines the authoritative verification protocol for Minecraft Java Edition 1.21.11 datapacks generated by **MinecraftAI**.

It enforces a strict distinction between:
1. **AUTOMATED HEADLESS VERIFIED**: Behaviors empirically demonstrated and verified by the automated headless Minecraft 1.21.11 server harness (`qa/runtime.py` and `test_step20_golden.py`).
2. **MANUAL IN-GAME REQUIRED**: Behaviors that inherently require a human player in an interactive graphical Minecraft 1.21.11 client.

The following items cannot be genuinely demonstrated by an automated headless server and **MUST be verified manually** in a graphical Minecraft 1.21.11 client:

* **Player Movement Speed Experience**:

  - Open the advancement tree in-game to visually confirm custom advancement icons, frame styles (task, goal, challenge), titles, and descriptions render cleanly without texture errors.

  - Verify `/scoreboard objectives setdisplay sidebar <obj>` visually renders on the right side of the player's HUD.

  - Place a crafting table, insert recipe ingredients, and manually pick up the crafted result from the crafting slot to verify client-server inventory synchronization.

### 3. Multiplayer & Real Player Joining
* **Player Join Scoreboard Initialization**:
  - Verify that a newly connected client player joining an active server receives initial scores dynamically without desynchronization.
* **Multi-Client Concurrency**:
  - Test two simultaneous client connections to verify global state machine events trigger once globally without per-client duplicate triggers.

## Part 4: Mandatory Regression Scenario: Stateful Rain Event

* **User Prompt**: `"When it is raining, give all players a diamond only once when the rain starts."`
* **Architectural Failure Mode Prevented**:
  - Pre-Step 13 defect: `#minecraft:load` evaluated `@a`, which was empty on boot. Joining players had unset scores.
  - Tick loop continuously gave diamonds 20 times per second during rain because no latch was set.
* **Authoritative Solution Architecture**:
  1. `data/<ns>/function/load.mcfunction`:
     ```mcfunction
     scoreboard objectives add rain_state dummy
     scoreboard players set #global rain_state 0
     scoreboard objectives add mcai_debug dummy
     scoreboard players set #load_ran mcai_debug 1
     scoreboard players set #tick_count mcai_debug 0
     say [MinecraftAI] [LOAD OK] minecraft:load called <ns>:load.mcfunction
     ```
  2. `data/<ns>/function/tick.mcfunction`:
     ```mcfunction
     scoreboard players add #tick_count mcai_debug 1
     execute if score #tick_count mcai_debug matches 1 run say [MinecraftAI] [TICK OK] minecraft:tick registered & running <ns>:tick.mcfunction
     execute if score #global rain_state matches 0 if predicate <ns>:is_raining run say [MinecraftAI] [EVENT] Condition <ns>:is_raining met. Executing on_enter action(s).
     execute if score #global rain_state matches 0 if predicate <ns>:is_raining as @a at @s run give @s minecraft:diamond 1
     execute if predicate <ns>:is_raining run scoreboard players set #global rain_state 1
     execute unless predicate <ns>:is_raining run scoreboard players set #global rain_state 0
     ```
* **Verification Status**:
  - **Automated Headless**: **PASSED** (Verified in real Minecraft 1.21.11 server; 0 -> 1 on rain -> 0 on clear).
  - **Manual In-Game**: Ready for physical player observation of diamond inventory addition.

- Semantic retrieval works after a previous traceback fix.
- Targets such as `@s` pass target validation.
- Ambiguous requests can return a clarification state instead of forcing an arbitrary interpretation.
- `make me faster` has produced a speed effect in testing.
- Multi-action requests can produce multiple planned actions.
- Generic entity, item, and loot-table RAG retrieval operational for arbitrary mobs and items (verified on creepers, zombies, skeletons, spiders).
- Deterministic Datapack Generator v1 (`generator/`) operational: creates valid Java 1.21.11 datapacks (`pack_format: 94`), modifies entity loot tables while preserving original drops/conditions/random sequences, and produces reproducible JSON and ZIP files.
- Deterministic Datapack Validator / Tester (`validator/`) operational: validates directories and ZIPs, detects corrupt/unsafe archives, enforces 1.21.11 `pack_format: 94` and singular `loot_table` paths, validates item IDs against 1.21.11 knowledge base, and checks vanilla drop preservation.
- Automatic AI Repair Loop (`repair/`) operational: diagnoses deterministic validator errors against Minecraft knowledge, generates corrected implementation plans, feeds them into the deterministic generator, enforces configurable retry protection without infinite loops, and records comprehensive attempt histories (verified with 7 automated tests in `test_repair_loop.py`).
- End-to-End Pipeline Orchestration (`pipeline/`) operational: public entry point `run_minecraft_pipeline()` coordinates Understanding, RAG Knowledge Retrieval, Planner, Generator, Validator, AI Repair Loop, and Final Validated Datapack ZIP. Full integration verified across 8 automated tests in `test_pipeline.py` (creeper drops diamonds, skeleton drops iron, ambiguous clarification halt, invalid pack repair recovery, permanent failure reporting with attempt history, arbitrary spider->iron_ingot drops, and ZIP tamper detection).
- CLI entry point `run_pipeline.py` operational with stage progress indicators `[1/7]` to `[7/7]`.
- Authoritative pack format 94 / 94.1 audit completed: generator emits `pack_format: 94`, `min_format: [94, 0]`, and `max_format: [94, 1]` for universal compatibility.
- User-facing Web Interface (`web/`) operational: decoupled FastAPI backend with endpoints (`GET /`, `POST /api/generate`, `GET /api/download/{filename}`, `GET /api/health`), path-traversal protected ZIP streaming, and modern Obsidian & Emerald dark-mode single-page UI with visual 7-stage tracker, dynamic outcome cards (Success with ZIP download, Clarification with refinement prompt, and Repair diagnostics), verified with 6 automated tests in `test_web.py`.
- Web CLI runner `run_web.py` operational (`python run_web.py --port 8000`).
- Multi-Mechanism Datapack Generator Architecture (`generator/mechanisms/`) operational: modular mechanism generators (`LootTableMechanismGenerator`, `FunctionMechanismGenerator`, `FunctionTagMechanismGenerator`, `AdvancementMechanismGenerator`) implementing `BaseMechanismGenerator` and returning `DatapackResource` objects. Supports custom functions (`data/<ns>/function/*.mcfunction`) with automatic leading slash sanitization, function tags (`data/<ns>/tags/function/*.json`) supporting `#minecraft:tick` and `#minecraft:load`, and advancements (`data/<ns>/advancement/*.json`). The validator verifies all mechanisms and rejects legacy 1.20- plural directories. Multi-mechanism composition and deterministic byte-identical zip reproducibility verified with 7 automated tests in `test_mechanisms.py` and 46/46 tests passing across all suites.
- Structured Planner → Generator Boundary (Step 11) operational: machine-readable `MechanismSpecification` data contract established in `generator/models.py`, `ai/planner.py`, and `generator/datapack_generator.py`. The Planner populates strongly typed mechanism parameters (`target`, `item`, `count`, `operation`, `commands`, `namespace`, `path`, `tag_name`, `values`, `criteria`, `rewards`) using retrieved Minecraft domain facts rather than vague prose. `validate_mechanism_specification` strictly validates specification completeness per mechanism type before resource generation. `DatapackGenerator.extract_mechanisms()` directly maps specifications into deterministic mechanism definitions (`to_*()` methods) while preserving backward compatibility for legacy minimal plans. Dynamic clarification pauses and arbitrary mob/item genericity verified with 13 automated tests in `test_planner_boundary.py` and 59/59 tests passing across the entire project repository.
- Custom Recipe Mechanism Generation & Validation (Step 12) operational: modular `RecipeMechanismGenerator` (`generator/mechanisms/recipe_mech.py`) generating valid Java 1.21.11 recipes (`minecraft:crafting_shaped`, `minecraft:crafting_shapeless`, `minecraft:smelting`, `minecraft:blasting`, `minecraft:smoking`, `minecraft:campfire_cooking`, `minecraft:stonecutting`) with singular `data/<namespace>/recipe/` directory structure and 1.21+ `result: {"id": ..., "count": ...}` schema. `MechanismSpecification` expanded with strongly-typed recipe fields, validated deterministically via `validate_mechanism_specification()`, and consumed directly by `DatapackGenerator`. `DatapackValidator` actively rejects obsolete plural `recipes/` directories (`OBSOLETE_PATH`), checks JSON syntax, verifies pattern-key matching in shaped recipes, and validates all input and result item IDs against the authoritative 1.21.11 item knowledge base. Verified with 12 automated tests in `test_recipes.py` and 71/71 tests passing repository-wide with zero regressions.
- Custom Predicate Mechanism Generation & Validation (Step 13) operational: modular `PredicateMechanismGenerator` (`generator/mechanisms/predicate_mech.py`) generating valid Java 1.21.11 predicates (`data/<namespace>/predicate/*.json`) with singular `predicate/` directory layout. Supports all 19 authoritative 1.21.11 condition types discovered in server jar bytecode (`weather_check`, `time_check`, `random_chance`, `entity_properties`, `match_tool`, `location_check`, `reference`, `value_check`, `enchantment_active_check`, `all_of`, `any_of`, `inverted`, etc.). `PredicateDefinition` model added to `generator/models.py`; `MechanismSpecification` expanded with `condition_type`, `condition_params`, `terms`, `term`; `validate_mechanism_specification()` strictly enforces predicate completeness. DatapackValidator Section 10 validates predicate condition types, parameter constraints, recursive composite term trees, item IDs in item predicates, entity IDs in entity predicates, and actively rejects obsolete plural `predicates/` directories (`OBSOLETE_PATH`). Generic predicate knowledge registry added to `knowledge/predicates/java/1.21.11/predicates.json` and indexed by `knowledge_retriever.py`. Verified with 8 automated unit tests in `test_predicates.py` and verified live end-to-end with real LLM inference in production (`add_a_predicate_that_checks_if_it_is_raining.zip`), with 80+ tests passing repository-wide with zero regressions.
- Runtime State Machine Integration Resolution (Step 13 Follow-up) operational: investigated Minecraft 1.21.11 server execution context semantics. Resolved empty `@a` selector evaluation during `#minecraft:load` and global vs per-player desynchronization. Planner system prompt updated with Rules 24 & 25 for global state machines (`#global` score holders) and per-player state machines (dynamic tick initialization). DatapackValidator expanded with `EMPTY_SELECTOR_ON_LOAD` static warning and documented limits of offline static validation vs 20Hz game-loop runtime simulation. Verified with 4 automated tests in `test_state_machine.py` and live Minecraft 1.21.11 server testing.
- Autonomous Datapack QA, Verification & Auto-Repair (Step 14) operational: introduced dedicated `qa/` package (`qa.models`, `StaticSemanticAnalyzer`, `AutonomousQAReviewer`, `QARepairEngine`, `RuntimeTestRunner`). Inspects the complete generated datapack across file completeness, cross-file reference integrity, command syntax/ordering, execution context (`as @a at @s`), and state-machine temporal logic (initialization, player join race conditions, transition latches, reset conditions). Compares implementation against original user request via `IntentVerificationResult`. AI diagnosis feeds structured `MechanismSpecification` updates into deterministic regeneration—strictly prohibiting arbitrary file patches. Enforces bounded repair loop with repeated-failure abort protection and establishes a strict final READY gate requiring structural validation, QA review, intent verification, and runtime simulation to pass before marking a datapack `READY` / `verified`. Verified with 14 automated tests in `test_qa.py` (including the generic rain regression and unrelated semantic regression) and confirmed live in production. 97/97 tests pass repository-wide with zero regressions.
- Planner → Generator Boundary: Structured Actions and Deterministic Command Synthesis (Step 15) operational: replaced raw command strings in the AI Planner with strongly-typed `ActionSpecification` schemas (`give_item`, `apply_effect`, `clear_effect`, `set_weather`, `execute_command`) and context models (`ActionContext`). Implemented deterministic command compilation (`compile_action_to_command()`) in `generator/mechanisms/function_mech.py` synthesizing syntax-valid, context-aware Minecraft 1.21.11 commands. Promoted state machines to first-class specifications (`StateMachineSpecification`) with a dedicated generator (`StateMachineMechanismGenerator` in `generator/mechanisms/state_machine_mech.py`) emitting `load.mcfunction`, `tick.mcfunction`, and `#minecraft:load`/`#minecraft:tick` tags with explicit `"replace": false`. Added intelligent multi-mechanism resource consolidation in `DatapackGenerator`. Updated `QARepairEngine` to produce structured action repairs. Verified with 9 automated tests in `test_step15_boundary.py` and empirical live server tests with zero regressions.
- Function Tag Minimal Formatting, Multi-Datapack Aggregation & Dangling Reference Sanitization operational: confirmed via `server-1.21.11.jar` bytecode that `"replace"` defaults to `false` (`TagFile` codec). `FunctionTagMechanismGenerator` and `StateMachineMechanismGenerator` omit `"replace"` by default for minimal canonical format (`{"values": [...]}`), preserving `"replace": true` only when explicitly specified. Standard game loop tags (`tick`, `load`) route to `data/minecraft/tags/function/`. `DatapackGenerator` merges tag values non-destructively and runs post-generation tag sanitization to strip dangling references, preventing Minecraft's all-or-nothing tag drop (`TagLoader.build()`). `DatapackValidator` accepts `"replace": false` as valid Minecraft syntax, checks boolean types, warns on `MISPLACED_GAME_LOOP_TAG`, and validates tag references. Tag knowledge added under `knowledge/tags/` and indexed into Planner context. Verified with multi-datapack aggregation tests in `test_generator.py`, tag tests in `test_mechanisms.py`, and validator tests in `test_validator.py`. 100% test pass rate across all repository suites.
- Step 15 Architectural Corrections (Escape Hatch Auditing & Strict Duration Validation) operational: `raw_command` removed from the public `action_type` schema presented to the Planner while preserved as an audited internal escape hatch. `FunctionMechanismGenerator.synthesize_action()` emits visibility warning `logger.warning("AUDIT: ActionSpecification used raw_command escape hatch: '%s'", raw)`. Strict duration validation enforces integer contract (rejecting all floats including 30.5, 0.5, 30.0 and float strings, booleans, negatives/zeros, and non-duration strings, while accepting integers >= 1, digit strings, case-insensitive "infinite", and None). Verified with 12 automated boundary tests in `test_step15_boundary.py` and full test suite without regressions.

## Known issues / gaps
- `10 times faster` is not yet interpreted reliably.
- Some combined requests still need better generic clarification when a property is underspecified, such as attack damage.
- Offline static simulation approximates tick loops; full live server execution requires headless server runtime harness (documented in `RuntimeTestRunner`).
